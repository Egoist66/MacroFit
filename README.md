# MacroFit

Дневник питания на Vue 3, TypeScript, Element Plus, Pinia и Vue Router.
Интерфейс повторяет дизайн `design.png`: дашборд с калориями и БЖУ,
последними приёмами пищи, целью, недельной статистикой и настройками.

## Запуск

```bash
pnpm install
pnpm dev
pnpm build
```

## Архитектура

Проект организован по предметным областям (domain-based design).

```
src/
  domains/
    nutrition/
      components/      # презентационные компоненты домена
      composables/     # вся логика экранов и форм
      constants/       # идентификаторы и ключи домена
      data/            # стартовые данные
      services/        # сервис хранения состояния питания
      stores/          # бизнес-логика домена (Pinia)
      types/           # типы и контракты сущностей
  components/
    layout/            # каркас приложения и навигация
    ui/                # переиспользуемые UI-примитивы
  composables/         # общие композаблы (доступ к сервисам)
  plugins/             # глобальные плагины приложения
  services/            # DI-контейнер и контракт сервисов
  router/              # маршруты и конфигурация роутера
  views/               # композиция страниц из доменных компонентов
  assets/              # глобальные стили и дизайн-токены
```

### Правила

- Бизнес-логика и состояние живут в `stores`.
- Логика экранов, форм и вычислений — в `composables`.
- Компоненты отвечают только за отображение и события.
- Все сущности и публичные функции документированы JSDoc-комментариями.
- Асинхронные операции построены на `async/await`.
- Вёрстка адаптирована от широкого десктопа до мобильных экранов:
  на мобильных боковое меню превращается в нижнюю навигацию.

### Сервисы и сохранение состояния

Сервисы создаются как классы и подключаются глобально плагином
`createServicesPlugin`. Экземпляры собираются в `createAppServices()`
и передаются в плагин один раз в `main.ts`. Например,
`NutritionStorageService` отвечает за сериализацию состояния питания.

Получить сервисы в компоненте или композабле можно через типизированный
`useAppServices()`, а конкретный сервис — через `useNutritionStorage()`:

```ts
const { nutritionStorage } = useAppServices()
const storage = useNutritionStorage()
```

Сохранение в localStorage реализовано глобальным Pinia-плагином
`createPiniaPersistencePlugin`. Стору достаточно указать опцию
`persist: true`: плагин восстановит state при создании и будет
перехватывать изменения через `$subscribe`, включая мутации внутри
асинхронных actions. Сервис плагин получает через тот же DI-контейнер,
что и остальное приложение. Ручные вызовы сохранения в сторах не нужны.
Старые сохранения с ценностью порции автоматически мигрируют в формат
«на 100 г».

### Расчёт пищевой ценности

Все формулы собраны в `utils/nutrition-calculations.ts`:

- пищевая ценность хранится на 100 г, порция считается как
  `значение_на_100г × вес / 100`;
- если калорийность не указана, она считается по БЖУ:
  `4 × белки + 9 × жиры + 4 × углеводы`;
- при наличии ккал производителя приоритет всегда у неё;
- итоги дня — сумма пересчитанных порций;
- доля калорий из макронутриента:
  `ккал_макро / ккал_итог × 100`.
